# Anki：加卡与同步

前提是用户已配置可访问的 Anki 实例、AnkiConnect、已登录的 AnkiWeb 账号，并授权本次加卡。技能不包含账户凭据，也不自动部署云服务器。

上游入口：[AnkiConnect](https://git.sr.ht/~foosoft/anki-connect)。运行时先检查当前连接的工具 schema 或当前上游文档，使用实际提供的接口；下面列的是常见 AnkiConnect 操作名称，不替代版本核实。

## 固定执行顺序

1. 检查连接与版本，确认目标牌组、笔记类型及7字段名称。只读操作常见为 `version`、`deckNames`、`modelNames`、`modelFieldNames`。
2. 调用同步（通常为 `sync`），等待已确认的完成状态后再加卡。同步失败、需要登录、出现全量同步提示时，停止加卡，保留准备文件。
3. 查询目标牌组已有笔记（通常为 `findNotes`、`notesInfo`），按 `Word` 的NFKC、空白归一化与忽略大小写值去重。不要仅凭文件名或日期判定重复。
4. 按 `assets/card-template.md` 配置约定字段；读取现有模板与字段，不能直接覆盖用户已有笔记类型。创建/改变笔记类型或模板可能导致全量同步，先说明具体变更并取得确认。
5. 使用生成的 `notes.json` 数据加入缺失词（常见为 `addNotes`）。逐项保存成功返回的 note ID 和失败项；部分成功时不重复提交整批，也不自动删除成功项。
6. 再次同步并确认结果。如果最后同步失败，报告“已加卡，尚未完成云端同步”，下次先同步并去重后继续。
7. 告知手机端登录同一 AnkiWeb 账号并同步。仅在有设备端证据时声称手机已经收到。

不要自动调用全量上传/下载、删除牌组、重置进度或覆盖远端集合。用户要求的常规加卡授权不包含上述破坏性操作。涉及全量上传时，先确认具体方向、数据来源和影响。

## 连接位置

云端 Linux Anki 应有持久化数据目录，运行中的 AnkiConnect 与已登录的同步账户。优先通过已有安全连接或本地 SSH 转发访问，不能将用户的账号、Cookie、API key、实际服务地址或同步日志上传到此仓库。

仅有模板/TSV 文件时，完成离线文件交付；不要把本地输出等同于已入库。
