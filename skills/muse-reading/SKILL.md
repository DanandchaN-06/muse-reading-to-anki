# Muse：兴趣阅读到 Anki

让读者先被内容吸引，再从语境里挑词，最后在手机上间隔重复。按用户正在进行的阶段继续，不要求每次从选文重新开始。

这是可移植的 `SKILL.md` 技能包；不假定 Muse 存在某个未验证的专用 API。通过当前宿主实际可用的浏览、文件、调度和 Anki 工具执行。

## 首次使用

沿用会话里已提供的兴趣、词库和目标。只补问缺少且会影响当前工作的内容：

- 兴趣与来源：示例为欧美音乐、电影、趣味科普、摇滚/爵士史；来源可选 Rolling Stone、Pitchfork、BBC、The Guardian、NPR、Scientific American。
- 目标词库与排除词库：支持任何英语目标词库；六级仅为随包示例。
- 阅读篇幅可由用户自行选择，700–900 英文词仅为默认建议；生成时把选择传给 `--min-words` 和 `--max-words`。生词表默认 15–25 词。
- 制卡默认牌组「阅读单词」；同步需要已配置、已授权的 Anki 连接。

参考 [配置与数据格式](references/data-formats.md)。随包词表在 `assets/wordlists/`；它们由用户提供，不称为官方大纲。源文件和派生结果的统计见该目录的说明。

## 选文与改写

1. 利用当前宿主的联网工具核实文章原页、来源和发布日期。每轮默认提供 4 篇候选，每篇包含中文标题、1–2 句简介、原文词数（无法精确取得则标估算或未知）、来源、发布日期和原链接。轮换兴趣，避免重复推荐。
2. 用户选定后才处理正文；已选定文章则直接继续。无法获取全文时说明证据范围，不把搜索摘要当全文，也不编造原文发布日期或引文。
3. 用本地脚本计算目标差集，不靠模型估计：

   ```bash
   python scripts/muse.py vocab --target assets/wordlists/raw/cet6.txt --exclude assets/wordlists/raw/cet4.txt --exclude assets/wordlists/raw/gaokao.txt --out work/target-vocab.json
   ```

   算法为目标集合减去排除集合的并集。保留多词词条，不擅自词干化或合并词族。记录实际数量；不要固定写成 1174。
4. 按用户选择的篇幅写成自主表达的学习稿（未指定时默认700–900词）；让适用的目标词自然进入语境，避免机械替换破坏语义或搭配。长文压缩；短文扩写标注扩写部分，明确补充信息的依据。尊重当前运行环境的版权及引用边界，不绕过付费墙，不把受限全文逐句洗写。
5. 生词表优先选择正文中出现的目标词。数量不足时如实说明，并区分补充词；释义针对本句词义。保留输入文章、学习稿和来源元数据的对应关系。

## 制作阅读器

按 [数据格式](references/data-formats.md) 保存文章 JSON，再运行：

```bash
python scripts/muse.py reader --article work/article.json --out work/reader.html
```

使用 `assets/reader-template.html` 的奶油白、衬线正文、暖橙色和黄色选词样式。预置词有虚线，点击显示中文；任意英文单词可选中，读完导出词/释义/所在句的三列 TSV。手机下载或剪贴板受限时提供可手动复制的文本框，不宣称所有 App 都支持下载。

输出后实际打开阅读器，检查词义弹窗、同词选择/取消和 TSV 导出。特别检查重复出现的单词是否对应被点击的那一句。多词词条可以参与差集，但阅读器逐词点击；不能把没有实现的整词组交互说成已支持。

## 用户选词后制卡

读取用户导出的 TSV；以用户所选为准，不擅自将全部预置词入库。

- 7 字段：`Word`、`Phonetic`、`POS`、`Definition`、`Example`、`ExampleCN`、`Cognates`。
- 正面只考认读：单行衬线单词＋音标。
- 背面：斜体橙色词性、中文释义、黄色加粗目标词的原文例句、例句翻译、常用同源词。
- 原文例句指读者实际阅读文本中的句子。优先逐字保留，不把改写前原文与学习稿混为一谈；记录句子来自哪一版文本。
- 缺释义、音标、译文、同源词时补齐并核查。没有可靠同源词可留空，不把近义词当同源词。不要为了凑词族强加罕见词。
- 若确实缺原句，可补写并标记 `ai_supplement`，不要冒充原文例句。
- 用用户当地日期打标签；按忽略大小写的词条去重。

将卡片按 [数据格式](references/data-formats.md) 写成 JSON，验证并导出：

```bash
python scripts/muse.py cards --input work/cards.json --article work/article.json --out-dir work/anki
```

脚本会生成 7 字段 TSV 和 AnkiConnect 可用的笔记数据，并验证原文例句确实存在。阅读器的三列 TSV 不是完整七字段牌组，需要经过补全与字段映射。

## 同步与每日运行

用户要求加入或同步卡片时，读 [Anki 同步](references/anki-sync.md)，调用当前环境真实存在的接口。保持“同步拉回 → 检查和去重 → 加卡 → 同步推送”的顺序；不改变用户复习进度。

用户明确要求定时选文时才创建调度任务，沿用已授权的时间和时区；只准备候选，不替用户选择文章或自动加入新卡。技能文件本身不会创建后台服务。调度工具或连接未配置时完成可离线部分，并说明尚缺哪一项。

交付时区分：已准备的文件、已加入的卡片、已确认完成的同步。不能因为本地 TSV 生成成功，就声称手机已收到卡片。
